Módulos del Sistema

Desglose detallado de la funcionalidad e implementación de cada módulo

🍽️ Módulo de Productos

Paquete: product_management

Responsabilidad: Gestionar productos, categorías e ingredientes

Entidades:

  • category: Categorización de productos
  • product: Información de productos
  • ingredient: Ingredientes base
  • product_ingredient: Relación producto-ingrediente

API Endpoints:

GET /api/patients GET /api/patients/{id} POST /api/patients PUT /api/patients/{id} DELETE /api/patients/{id} GET /api/patients/{id}/history POST /api/patients/{id}/history

📊 Database Schema

Table Columns Relationships
patient id, name, last_name, birth_date, phone, email 1:N with medical_history
medical_history id, patient_id, description, date N:1 with patient

👨‍⚕️ Doctors Module

Schema: doctors_schema

Responsibility: Handle medical professional information and schedules

Entities:

  • doctor: Medical professional information
  • shift: Doctor work schedules

API Endpoints:

GET /api/doctors GET /api/doctors/{id} POST /api/doctors PUT /api/doctors/{id} DELETE /api/doctors/{id} GET /api/doctors/{id}/shifts POST /api/doctors/{id}/shifts

📊 Database Schema

Table Columns Relationships
doctor id, name, last_name, specialty_id, phone, email 1:N with shift, N:1 with specialty
shift id, doctor_id, date, start_time, end_time N:1 with doctor

📅 Appointments Module

Schema: appointments_schema

Responsibility: Control appointment scheduling and management

Entities:

  • appointment: Scheduled appointment information
  • room: Hospital physical spaces
  • hospital: Medical center information

API Endpoints:

GET /api/appointments GET /api/appointments/{id} POST /api/appointments PUT /api/appointments/{id} DELETE /api/appointments/{id} GET /api/appointments/patient/{id} GET /api/appointments/doctor/{id} GET /api/rooms GET /api/hospitals

📊 Database Schema

Table Columns Relationships
appointment id, patient_id, doctor_id, room_id, appointment_type_id, status_id, date, time N:1 with patient, doctor, room, appointment_type, status
room id, name, hospital_id N:1 with hospital, 1:N with appointment
hospital id, name, address 1:N with room

⚙️ Parameterization Module

Schema: parameterization_schema

Responsibility: System configuration and master data

Entities:

  • role: User roles in the system
  • appointment_type: Available consultation types
  • appointment_status: Possible appointment statuses
  • specialty: Medical specialties

API Endpoints:

GET /api/roles GET /api/appointment-types GET /api/appointment-statuses GET /api/specialties POST /api/roles POST /api/appointment-types POST /api/appointment-statuses POST /api/specialties

📊 Database Schema

Table Columns Relationships
role id, name 1:N with user
appointment_type id, name, description 1:N with appointment
appointment_status id, name 1:N with appointment
specialty id, name, description 1:N with doctor

🔐 Security Module

Schema: security_schema

Responsibility: User authentication and authorization

Entities:

  • user: User authentication information

API Endpoints:

GET /api/users GET /api/users/{id} POST /api/users PUT /api/users/{id} DELETE /api/users/{id} POST /api/auth/login POST /api/auth/register

📊 Database Schema

Table Columns Relationships
user id, username, password, role_id, patient_id, doctor_id, active N:1 with role, optional N:1 with patient/doctor

Security Features:

  • JWT token authentication
  • Password encryption (BCrypt)
  • Role-based authorization
  • Session management
